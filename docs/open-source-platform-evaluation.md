# Open-source platform evaluation

Phase 1 deliverable for the NautilusTrader replay spike. This evaluation reviews the current
versions, licenses, and capabilities of the open-source components relevant to deterministic replay,
backtesting, paper trading, portfolio accounting, and eventual execution for Polymarket BTC
five-minute prediction markets.

All facts below were gathered from primary sources only: official repositories, official
documentation, package metadata (PyPI / crates.io / npm), and source code. GitHub star counts are
intentionally **not** used as a decision criterion and are omitted.

Review date: 2026-08-05.

## Scope

The existing TypeScript recorder remains the authoritative lossless acquisition and audit layer.
This evaluation asks whether any combination of the components below can replace the hand-written
replay/backtest/portfolio/execution roadmap components without weakening the recorder or schema-v2
semantics.

## Cross-cutting observations

1. **No component preserves raw frame text or recorder lineage.** Every official SDK and the
   Nautilus adapter decode to typed domain events and discard the exact wire bytes, per-message
   text, dedup metadata, and connection-generation identity. The TypeScript recorder must remain the
   lossless audit layer; lineage must be re-attached in the adapter.

2. **Chainlink reference prices are not modeled anywhere in Nautilus.** The only official component
   that touches Chainlink RTDS is the Rust SDK's `rtds` feature, and it is a live transport. A
   custom Nautilus data type is required to represent settlement reference prices without semantic
   distortion (not as a trade, quote, mark price, or fill).

3. **Nautilus is the only component that provides replay, backtesting, matching/fill simulation,
   portfolio accounting, and execution in one deterministic engine.** All Polymarket SDKs are
   transport/SDK layers only.

4. **The Nautilus Polymarket adapter is reusable for live execution and live market data, but not
   directly reusable for replaying schema-v2 recordings.** It expects a live CLOB/Gamma client.
   Replay requires converting schema-v2 events into Nautilus catalog data and driving a backtest
   node, which is custom work.

5. **License landscape.** Polymarket SDKs are MIT. NautilusTrader is LGPL-3.0-or-later (weak
   copyleft, library-level). Using Nautilus as an unmodified dependency does not force the project's
   own code to LGPL, but modifying the Nautilus core/adapter would. Linking considerations should be
   confirmed against the project's distribution model.

6. **Python/Windows compatibility.** NautilusTrader ships `cp312`-`cp314` Windows wheels
   (`win_amd64`). The project pins `uvloop` to non-Windows platforms only, so Windows is supported
   for development. CI should run on `ubuntu-latest` to match the existing TypeScript job and avoid
   platform-specific event-loop differences.

the replay path consumes only local schema-v2 fixtures. The SDKs are evaluated here for the
adoption-decision build-versus-adopt matrix in Phase 11.
